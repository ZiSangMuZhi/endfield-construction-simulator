# 架构说明

## 目标

工具保持纯前端、轻量、离线可用。UI、布局模型、游戏数据和模拟内核必须分离；未来配方更新只替换数据，不修改算法。

## 计划模块

- `planner`：格点、坐标、占地、朝向、端口与物流线。
- `catalog`：设备、物品、配方和游戏版本数据。
- `simulation`：固定时间步/离散事件混合模拟。
- `analysis`：理论吞吐、实际吞吐、利用率和等待原因。
- `persistence`：版本化 JSON 蓝图与 localStorage 适配器。

## 核心状态机

设备状态依次为 `idle`、`starved`（缺料）、`working`、`blocked`（输出堵塞）、`unpowered`。每个生产周期先原子扣除输入，周期结束后尝试写入输出缓存；写入失败进入 `blocked`。利用率按观察窗口内 `workingTime / poweredTime` 计算。

## 物流拓扑（当前实现）

当前开放的每个传送带格保存 `entry` 与 `rotation`（出口）两个四向方向。相邻格只有在上游出口指向下游、且下游入口指回上游时才构成有向边；单纯接壤不会连接。拖拽铺设时，光标每进入下一个正交相邻格便完成一次方向握手，并同步修正前一格的出口。管道仍保留兼容数据类型，但不出现在当前工具栏、默认蓝图或模拟线路中。

运行时从无入边节点出发遍历有向边，把连续格段汇总为线路。显示层为每条线路生成一条带二次贝塞尔圆角、圆头和圆角连接的 SVG 双层描边，因此直线与弯道之间没有格点节点或接缝。每格的方向箭头是静态 SVG 标记；物品图标沿同一条整线路径运动，并按线路格数错峰显示，跨格与弯道转交不会在单格边界重新开始。环线由未访问节点补充遍历，避免遗漏。

实体编辑以共享 `id` 为边界：3×3 设备的九个格属于同一实体，复制、旋转和移动均原子更新整个实体。设备视觉仅由根格绘制一次完整占地面板，其他占格保持透明；端口占格只承载端口，不再叠加网格边框。移动采用“准备放置 → 校验边界/碰撞 → 一次提交”，非法目标不会移除源实体。设备旋转同步改变所有占格的朝向，输入/输出端口依据朝向重新映射到对应边缘中央。

设备模拟状态同样以实体 `id` 为边界。每个生产实体单独检查输入侧相邻传送带是否朝向设备、输出侧相邻传送带是否以正确入口握手；缺少输入进入 `starved`，有输入但无输出进入 `blocked`，只有两侧连通才推进自己的周期。实体 ID 参与周期相位偏移，因此合法连接的复制设备也不会被强制同步到同一帧。

供电桩为 `2×2` 实体，范围模型是围绕设备中心的 `12×12` 轴对齐方形。生产设备占地矩形与任一供电范围矩形相交即视为已供电；否则进入 `unpowered`，此状态优先于暂停、缺料与阻塞且进度为零。供电范围来自集中计算结果，状态判断和可视化共用同一份数据，避免显示范围与模拟范围不一致。

显示层固定为网格 → 物流本体 → 运输物品 → 设备本体 → 端口 → 选择状态。传送带伸入端口时会被设备和端口遮盖，不会浮在设备面板上方。

## 性能边界

布局编辑只更新受影响格子。模拟不依赖 React 渲染循环；后续迁入 Web Worker，主线程只接收低频快照。目标是在 1000 个设备、60 秒模拟窗口下保持交互流畅。
