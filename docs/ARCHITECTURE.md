# 架构说明

## 目标

工具保持纯前端、轻量、离线可用。UI、布局模型、游戏数据和模拟内核必须分离；未来配方更新只替换数据，不修改算法。

## 计划模块

- `planner`：格点、坐标、占地、朝向、端口与物流线。
- `catalog`：设备、物品、配方和游戏版本数据。
- `simulation`：固定时间步/离散事件混合模拟。
- `analysis`：理论吞吐、实际吞吐、利用率和等待原因。
- `persistence`：版本化 JSON 蓝图与 localStorage 适配器。

## 核心状态机

设备状态为 `idle`、`starved`（缺料）、`running`、`blocked`（产出库存已满）、`unpowered`。固定步长为 250ms；一次 `setSimulation` 同时提交时钟、进度、库存和传送带位置，避免旧实现中 `setTick` 后再由 effect 二次提交造成同一时刻两次整页渲染。配方到时只产生一次完成事件。当前利用率使用运行设备占比，产销分析以 1 秒桶保留 5 分钟历史与额外 30 秒平滑前导区。

## 物流拓扑（当前实现）

每个物流格保存 `entry` 与 `rotation`（出口）两个四向方向。相邻格只有在上游出口指向下游、且下游入口指回上游时才构成有向边；单纯接壤不会连接。传送带保存在主网格，管道保存在独立 `pipeGrid`，因此同一坐标可以同时存在一条传送带和一条管道。两层分别解析拓扑、选择和中段改线；寻路避开设备但允许经过同层物流，提交时原子覆盖重叠格。

运行时从无入边节点出发遍历有向边，把连续格段汇总为线路。显示层为每条线路生成一条带二次贝塞尔圆角、圆头和圆角连接的 SVG 双层描边，因此直线与弯道之间没有格点节点或接缝。每格的方向箭头是静态 SVG 标记；物品图标沿同一条整线路径运动，并按线路格数错峰显示，跨格与弯道转交不会在单格边界重新开始。环线由未访问节点补充遍历，避免遗漏。

实体编辑以共享 `id` 为边界：同一设备的占格属于一个实体，复制、旋转和移动均原子更新整个实体。传送带则按有向连续线路组成可编辑对象。单击任一占格即可选中；移动/复制阶段把相对占格随指针投影到网格，实时生成有效或冲突吸附框，单击时才提交。设备视觉仅由根格绘制一次完整占地面板，其他占格保持透明；端口由 `EQUIPMENT_LAYOUTS` 中的 `inputs[]` / `outputs[]` 数据解析为独立端口。设备旋转同步旋转占地、端口坐标与朝向；复制设备分配新 ID，并从空库存、零进度开始。

设备目录使用 Pointer Events 和指针捕获携带稳定 `Kind`，鼠标与触摸共用同一事务。拖动过程中以画布 `getBoundingClientRect()` 投影真实占地，不创建临时实体；释放时再次检查主网格与管道层，合法才通过 `placeTool` 写入。目录按钮没有单击放置状态，画布空格也不会读取上一次拖拽的设备类型重复放置。

物流桥和管道桥都建模为带两组配对输入/输出端口的 1×1 无加工设备。桥的同索引输入输出形成独立轴，线路物品类型解析只沿匹配索引穿过桥；分流器按源实体轮询游标均分，汇流器把多条输入写入共享缓存后受单条输出吞吐约束。

设备长按手势由独立的指针状态机管理。`pointerdown` 记录实体、起点与 pointer ID，并捕获指针；420ms 内移动超过 14px 会在轮盘出现前取消。打开后用向量角度落入四个 90° 扇区，距离小于 30px 保持取消状态；`pointerup` 先进入 210ms 的 `confirming` 视觉阶段，再以显式实体 ID 调用与工具条相同的旋转、移动、复制或拆除事务。轮盘不复制业务逻辑，且 `pointercancel`、捕获丢失和 `Esc` 都会清理计时器。

设备模拟状态同样以实体 `id` 为边界。连续线路只要解析出源输出端口就具备收货资格；目标输入端口只决定末端能否卸货。运输层还要求源端拥有对应物品且线路首格有容量。每台设备持有独立 `input` / `output` 库存与配方进度；输入字典按物品介质分别统计，固体和液体各有 `50` 单位容量，任一对应入口满载只阻塞同介质线路。缺少配方输入进入 `starved`，产出库存没有容量时进入 `blocked`。

生产数据由 `MachineDefinition.recipes[]` 驱动。`MachineRecipe` 同时声明稳定配方 ID、`solid` / `fluid` 模式、多项输入、多项输出和周期；设备占格保存 `recipeId`，旧蓝图缺失时回退到设备首个配方。模拟完成事件会原子校验并扣除全部输入，再写入全部输出；线路物品、端口握手、库存面板、进度条和产销统计都读取同一条活动配方。切换配方时只清零该设备当前周期，保留库存；`PortSpec.modes` 让精炼炉、灌装机、种植机在液体模式下增加对应管道端口，而不删除已有线路。`PortSpec.outputIndex` 允许同一种物流介质的多个输出口分别绑定活动配方的特定输出项；提纯机因此可让上、下管口分别发送副产物和主产物，而不是都选择第一个流体输出。

每个在途单位记录 `routeId`、物品 ID、当前连续格位置 `position` 和上一快照位置 `previousPosition`。时间参数集中在 `lib/belt-timing.ts`，吞吐、空间位移、单位间距和每格容量是四个独立字段。普通传送带每 8 个 250ms 步长最多发 1 件，即 `30/min`，每格最多 1 件；管道当前每 2 步最多发 1 单位，即 `120/min`，每格缓存 4 单位。阻塞会压缩队列到相邻槽位，但视觉间距不参与计算下一次发货时间。

运输显示不使用与 SVG 文档时间轴绑定的 `animateMotion`。`CargoRouteSprites` 只为传送带线路启动一个 `requestAnimationFrame`，批量更新全部固体图标；管道把在途单位按位置汇总到每格，以 `0–4` 占用率映射内填充粗细，不创建液体图标或逐帧回调。React 仍只需每秒提交 4 次状态。

传送带草稿分为已确认路径点和鼠标临时段。已确认段保存在 `BeltDraft`；鼠标只记录当前网格目标，派生层用与点击提交相同的 A* 障碍集合实时计算临时段。端口候选必须同时匹配当前 `TransportKind`。既有同层物流不是寻路障碍：提交时覆盖重叠格并清理受影响线路的在途状态；若终点落在既有线路，`BeltJoin` 复制该格出口方向以接续原下游。中段改线仍由 `BeltReplan` 原子替换下游，取消不改动网格。

调度不依赖全局取模边界。每条线路用 `laneReadyAt` 记录下一次最早发货时刻，并用 `beltLaneCanAccept` 验证货物数量小于格数且尾货已经离开首格。调度器先按源设备分组可用输出线路：库存至少等于当前就绪线路数时，同一模拟步向每条线路各发 1 件；库存不足时从该设备持久化的 `routeCursor` 开始轮询。这样单件产出平均分配，而已有缓存可以让所有未阻塞出口保持各自满速。

每次模拟步从线路最前方开始推进物品。若目标输入库存有空间，最前物品到达线路长度位置后写入库存并移除；若目标已满或根本没有输入端，最前物品被限制在 `格数 - 0.5`，后车依次被限制在前车后 1 格。线路达到“物品数等于格数、首尾都落在半格中心”时判定满载，源设备停止向该线路发货，形成逐格可见的背压。

仓库取货口的 `itemId`、生产设备的 `recipeId` 都保存在实体各占格中。物品目录记录稳定 ID、简体中文名、分类、可选本地图标路径和可选流体颜色；线路元数据由源端实体实时解析，悬停流速、管道颜色和运动图标共用该结果。设备定义的图像路径同样可选。缺图时 `AssetThumb` 用名称与“待补图”渲染内容占位，SVG 运输层则以物品首字替代空图像节点，因此新增数据不依赖伪造素材也不会产生 404 请求。蓝图 v3 分开保存 `grid` 与 `pipeGrid`，同时保存设备库存、进度和产销历史，主动丢弃在途动画记录；载入 v1/v2 时把缺失的管道层与产销历史初始化为空，并让缺失配方 ID 的设备使用当前默认配方。

产销统计直接订阅模拟事务，而不从当前库存差值反推：机器配方完成时登记成品产出并登记被扣除的配方原料消耗；仓库取货口只有在货物真正进入线路时登记外部供给产出；仓库存货口交付没有消耗事件。原始事件按模拟秒合并到 `itemStats`，无新事件的模拟步复用旧数组，避免为延长历史而每 250ms 深拷贝。显示层一次派生产线涉及的全部物品，以 5 秒间隔生成 60 个图点，并用每点之前 30 秒的事件总量折算每分钟速率；卡片同时保留最近 5 分钟实际总量。重置事务通过全新 `SimulationState` 清空这些统计以及库存、进度、在途物流和线路历史，但不触碰 `grid` / `pipeGrid`。

供电桩为 `2×2` 实体，范围模型是围绕设备中心的 `12×12` 轴对齐方形。生产设备占地矩形与任一供电范围矩形相交即视为已供电；否则进入 `unpowered`，此状态优先于暂停、缺料与阻塞且进度为零。供电范围来自集中计算结果，状态判断和可视化共用同一份数据，避免显示范围与模拟范围不一致。

显示层固定为画布网格 → 物流外轮廓/液体填充 → 传送带物品 → 设备本体 → 介质端口图标 → 选择状态。端口占格拥有高于设备根面板和物流层的层级，线路伸入端口时不会覆盖端口图标；画布容器本身不绘制额外背景网格。

编辑器目录分为无实体占地的“工具”和可放置“设备”。设备分类使用游戏设备目录的简体中文分类键；筛选只改变目录呈现，不改变稳定 `Kind` 与存档数据。拆除统一经过 `deleteAt`：设备按实体 ID 删除全部占格并清理库存/进度，传送带按解析出的完整有向线路删除，按钮、`Delete` / `Backspace` 和右键入口共用该事务。

## 性能边界

端口和线路索引预先构建为按格查询的 `Map`，避免每个格子在每次渲染中扫描全部端口或线路。模拟每秒只提交 4 个 React 快照；货物的显示帧由局部 DOM 插值承担，不触发画布树重建。后续设备规模超过当前目标时再把 250ms 状态事务迁入 Web Worker。
