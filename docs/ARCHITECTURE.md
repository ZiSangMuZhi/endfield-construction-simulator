# 架构说明

## 目标

工具保持纯前端、轻量、离线可用。UI、布局模型、游戏数据和模拟内核必须分离；未来配方更新只替换数据，不修改算法。

## 计划模块

- `planner`：格点、坐标、占地、朝向、端口与物流线。
- `catalog`：设备、物品、配方和游戏版本数据。
- `simulation`：固定时间步/离散事件混合模拟。
- `analysis`：理论吞吐、实际吞吐、利用率和等待原因。
- `persistence`：版本化 JSON 蓝图与 localStorage 适配器。

## 核心状态机

设备状态为 `idle`、`starved`（缺料）、`running`、`blocked`（产出库存已满）、`unpowered`。固定步长为 100ms；进度、输入扣除和产出写入在同一状态事务内更新，配方到时只产生一次完成事件。当前利用率使用运行设备占比，观察窗口统计将在分析模块补齐。

## 物流拓扑（当前实现）

当前开放的每个传送带格保存 `entry` 与 `rotation`（出口）两个四向方向。相邻格只有在上游出口指向下游、且下游入口指回上游时才构成有向边；单纯接壤不会连接。构建状态保存显式路径点和由路径点展开的临时格序列；每次增加非相邻路径点时，带转弯惩罚的 A* 在当前画布边界内绕开设备、既有线路和已提交的草稿段。只有完成操作时才把整条草稿原子写入网格。管道仍保留兼容数据类型，但不出现在当前工具栏、默认蓝图或模拟线路中。

运行时从无入边节点出发遍历有向边，把连续格段汇总为线路。显示层为每条线路生成一条带二次贝塞尔圆角、圆头和圆角连接的 SVG 双层描边，因此直线与弯道之间没有格点节点或接缝。每格的方向箭头是静态 SVG 标记；物品图标沿同一条整线路径运动，并按线路格数错峰显示，跨格与弯道转交不会在单格边界重新开始。环线由未访问节点补充遍历，避免遗漏。

实体编辑以共享 `id` 为边界：同一设备的占格属于一个实体，复制、旋转和移动均原子更新整个实体。传送带则按有向连续线路组成可编辑对象。单击任一占格即可选中；移动/复制阶段把相对占格随指针投影到网格，实时生成有效或冲突吸附框，单击时才提交。设备视觉仅由根格绘制一次完整占地面板，其他占格保持透明；端口由 `EQUIPMENT_LAYOUTS` 中的 `inputs[]` / `outputs[]` 数据解析为独立端口。设备旋转同步旋转占地、端口坐标与朝向；复制设备分配新 ID，并从空库存、零进度开始。

设备模拟状态同样以实体 `id` 为边界。连续线路必须同时解析出源输出端口和目标输入端口才标记为 `valid`；运输层还要求源端拥有对应物品。每台设备持有独立 `input` / `output` 库存与配方进度，缺少配方输入进入 `starved`，产出库存没有容量时进入 `blocked`。没有输出线路时产物先进入缓存，缓存满后才阻塞生产。

每个在途物品记录 `routeId`、物品 ID、发货时刻、不可变 `travelTicks` 和预计到达时刻。时间参数集中在 `lib/belt-timing.ts`：普通传送带每条线路独立拥有 20 步（2 秒）的发货冷却，即 `30/min`；线路旅行时间为 `格数 × 20 步`。公开数据只确认 0.5 件/s 吞吐，没有单独公开空间移动速度，因此当前采用“一格等于一个物品间距”的可审计模型，即 0.5 格/s、每格 2 秒；该假设与已核实数据分开记录，后续获得实测后只需替换时序模块。

调度不依赖 `tick % 20` 的全局边界。每条线路用 `laneReadyAt` 记录下一次可发货时刻，避免暂停恢复或编辑拓扑时在同一 tick 重复发货。调度器先按源设备分组可用输出线路：库存至少等于当前就绪线路数时，同一模拟步向每条线路各发 1 件；库存不足时从该设备持久化的 `routeCursor` 开始轮询，发货后推进到完整线路数组中的下一位置。这样刚完成的一件产物会平均分配，而已有缓存可以让所有出口保持各自满速。显示层只渲染实际在途记录，不再按线路长度伪造物品。

目标输入库存连同已在途物品参与容量预留。目标已满时不再创建新发货事件；已经到达末端的记录保持在途并冻结于线路末端，直到目标有空间，形成可见背压。设备满载状态和红色外框来自同一容量计算。

仓库取货口的 `itemId` 保存在实体各占格中。物品目录记录稳定 ID、简体中文名、分类与本地图标路径；线路元数据由源端实体实时解析，流量面板和运动图标共用该结果。蓝图 v2 存档同时保存设备库存和进度，主动丢弃在途动画记录，载入后从一致的静态库存状态继续。

供电桩为 `2×2` 实体，范围模型是围绕设备中心的 `12×12` 轴对齐方形。生产设备占地矩形与任一供电范围矩形相交即视为已供电；否则进入 `unpowered`，此状态优先于暂停、缺料与阻塞且进度为零。供电范围来自集中计算结果，状态判断和可视化共用同一份数据，避免显示范围与模拟范围不一致。

显示层固定为网格 → 物流本体 → 运输物品 → 设备本体 → 端口 → 选择状态。传送带伸入端口时会被设备和端口遮盖，不会浮在设备面板上方。

编辑器目录分为无实体占地的“工具”和可放置“设备”。设备分类使用游戏设备目录的简体中文分类键；筛选只改变目录呈现，不改变稳定 `Kind` 与存档数据。拆除统一经过 `deleteAt`：设备按实体 ID 删除全部占格并清理库存/进度，传送带按解析出的完整有向线路删除，按钮、`Delete` / `Backspace` 和右键入口共用该事务。

## 性能边界

布局编辑只更新受影响格子。模拟不依赖 React 渲染循环；后续迁入 Web Worker，主线程只接收低频快照。目标是在 1000 个设备、60 秒模拟窗口下保持交互流畅。
